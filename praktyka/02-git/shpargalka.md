# Моя шпаргалка Git

| Команда | Що робить — своїми словами | Коли я її використаю |
|---|---|---|
| `git clone` | Копіює віддалений репозиторій на мій комп'ютер | Коли починаю працювати з існуючим репозиторієм |
| `git status` | Показує, які файли змінилися і що зараз підготовлено до коміту | Перед `add` і після нього |
| `git diff` | Показує зміни, які ще не додані до індексу | Щоб перевірити свої зміни |
| `git add` | Додає вибрані зміни до наступного коміту | Коли хочу підготувати зміни |
| `git commit` | Записує підготовлені зміни в історію Git | Коли завершив певну логічну частину роботи |
| `git push` | Відправляє локальні коміти на GitHub | Щоб зміни з'явилися у віддаленому репозиторії |
| `git log` | Показує історію зроблених комітів | Щоб переглянути попередні зміни |
| `git branch` | Показує існуючі гілки та поточну гілку | Щоб перевірити гілки репозиторію |
| `git checkout -b` | Створює нову гілку та одразу перемикається на неї | Коли починаю окрему частину роботи |
| `git merge` | Об'єднує зміни з іншої гілки з поточною | Коли хочу перенести готову роботу в основну гілку |

Передбачення №1

Питання: Де git status покаже eksperyment.txt?

Відповідь:
Моє передбачення: файл eksperyment.txt буде показаний у двох категоріях: зміни, підготовлені до коміту, та зміни, які ще не підготовлені. Це відбувається тому, що після git add до індексу потрапив «Рядок 2», а «Рядок 3» залишився тільки у робочій директорії.

Git показав файл у двох категоріях: зміни, підготовлені до коміту, та зміни, які не були підготовлені. Моє передбачення справдилося.

Передбачення №2

Питання: Що покажуть git diff і git diff --staged?

Відповідь:
Моє передбачення: команда git diff покаже доданий «Рядок 3», оскільки він ще не був доданий до індексу. Команда git diff --staged покаже доданий «Рядок 2», оскільки саме ця зміна вже була додана до індексу командою git add.

git diff показав «Рядок 3», а git diff --staged показав «Рядок 2». Моє передбачення справдилося.

Передбачення №3

Питання: Що потрапить у коміт без повторного git add?

Відповідь:
Моє передбачення: у коміт потрапить тільки «Рядок 2», який був доданий до індексу. «Рядок 3» у цей коміт не потрапить, тому що після його додавання до файлу команда git add повторно не виконувалася. Після коміту «Рядок 3» залишиться як незбережена в індексі зміна.

Після виконання git commit до коміту потрапив лише «Рядок 2». «Рядок 3» залишився незакоміченим. Моє передбачення справдилося.

## Розв'язання конфлікту

Під час конфлікту я залишив варіант `print("Вітаємо, користувачу!")`, оскільки він був у гілці `master` і краще відповідав основній версії програми.
Маркери конфлікту я видалив, щоб файл залишився коректним Python-кодом.
