# Висновок: три мови макета

```

== form_grid.py
  ✅ форма повна, поля в колонку з підписами, кнопки внизу праворуч
  ⭐ вікно розтягнули на 200 px — поля розтягнулись разом із ним

== form_pack.py
  ✅ форма повна, поля в колонку з підписами, кнопки внизу праворуч
  ⭐ вікно розтягнули на 200 px — поля розтягнулись разом із ним

== form_place.py
  ✅ форма повна, поля в колонку з підписами, кнопки внизу праворуч
  ·  вікно розтягнули на 200 px — поля лишились тієї самої ширини (для place це очікувано — запишіть у vysnovok.md)

Разом: 3 з 3 форм ✅   (мінімум для зарахування — grid і ще одна)
```

Для цієї форми найкраще підійшов **grid**: форма по суті є таблицею з двох стовпців (підписи й поля), і `sticky="e"` для підписів, `sticky="ew"` для полів та `columnspan=2` для заголовка й кнопок дали рівну колонку без жодних підрахунків ширини. Найважче було так: у **grid** — пам'ятати про `columnconfigure(1, weight=1)` (без нього поля не тягнуться, це показала спроба D), у **pack** — зробити колонку з потоку, для чого довелося дати підписам однакову `width=10` і загорнути кожен рядок у власну `Frame`, а прапорець вирівнювати порожнім підписом такої самої ширини, у **place** — рахувати x і y у пікселях вручну й притискати кнопки через `relx=1.0`, `rely=1.0` та `anchor="se"`.
Експеримент 1 (розтягування): у grid і pack поля розтягнулись разом із вікном (завдяки `weight=1` та `fill="x", expand=True`), у place поля лишились тієї самої ширини, бо координати в пікселях, а кнопки, прив'язані через `relx`, переїхали разом із правим краєм. Експеримент 2 («Abbrechen und zurück» замість «Скасувати»): grid і pack просто збільшили вікно (до 350 і 358 px) і кнопки не перекрились, а у place вікно лишилось 380 px, і довша кнопка наїхала на «Зареєструватись», бо її x було зафіксовано.
Отже, для форм, чий текст може змінитись (переклад), place не годиться; pack годиться, але колонка в ньому тримається на ручній `width`, а grid надійний найбільше.

## Додаткові завдання (⭐1–⭐4)

**⭐1.** У `form_grid.py` стоїть `columnconfigure(1, weight=1)`: при розтягуванні вікна тягнуться лише поля, а підписи лишаються на місці. `perevir.py grid` пише «⭐ … поля розтягнулись».

**⭐2.** Усі тексти `form_grid.py` лежать у словнику `PIDPYSY`, мову обирає `MOVA` («uk» або «de»). Німецькі підписи («E-Mail-Adresse:», «Telefonnummer:», «Registrieren») довші, і форма стала ширшою (≈404 px замість ≈350), але виглядає охайно: grid сам підбирає ширину стовпця підписів, а макет не змінювався.

**⭐3.** `vikno_ramky.py`: головне вікно складається через `pack` з трьох областей (смуга стану `side="bottom"`, форма `side="left"`, панель «Підказка» `side="right"`), а всередині рамки з формою працює `grid`. Смугу стану треба пакувати першою, інакше її витисне форма. Вікно розтягується без «з'їжджання»: поля ростуть, панель підказки лишається завширшки 200 px.

**⭐4.** `forma_z_opysu.py` читає `forma.yaml` і будує форму через grid (`tekst` → `Entry`, `parol` → `Entry(show="•")`, `chyslo` → `Spinbox`). Зміна YAML змінює форму без правки коду, а `forma_reiestracii.yaml` відтворює форму реєстрації. Це маленька зовнішня DSL: її кінцевий користувач — людина, яка вміє редагувати текстовий файл, але не пише на Python (наприклад, колега-адміністратор). Межа DSL — в обмеженому словнику: є лише три типи полів, прапорці й кнопки. Не можна описати валідацію, обробники натискань, залежність одних полів від інших чи нестандартне розташування, тому для таких речей усе одно потрібен код.
